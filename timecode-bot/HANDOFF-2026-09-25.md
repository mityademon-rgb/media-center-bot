**Состояние на 25 сентября 2026 года, 12:23 МСК.** Этот документ адресован следующему разработчику или ИИ. Отделяйте подтверждённое состояние от предположений. Не объявляйте развёртывание успешным, пока не проверены результат GitHub Actions, ответ службы и фактическая работа в Telegram.

## 1. Что это и куда заходить

- Бот: [@timemarphino_bot](https://t.me/timemarphino_bot). Ученик открывает ссылку, нажимает «Старт», выбирает Kids Lab или Media Lab, затем «Открыть TIMECODE». Кнопка приложения есть и в меню бота.
- Mini App: <https://timecode-lab.ru/tc/>. Если Telegram показывает старую оболочку, сначала проверить тот же путь с новым параметром `?v=YYYYMMDD-N` и файлы приложения; не менять Nginx без диагностики. Прямая страница без авторизации показывает вход, внутри Telegram используется Telegram WebApp.
- Основной сайт <https://timecode-lab.ru/> — отдельный сайт, не приложение. Его не перезаписывать при работе с ботом.
- Репозиторий: <https://github.com/mityademon-rgb/media-center-bot/tree/feature/timecode-media-bot/timecode-bot>. Ветка `feature/timecode-media-bot`. Исходники сервера — `timecode-bot/server.py`, рассылки — `timecode-bot/notification_delivery.py`, Mini App — `timecode-bot/static/`.
- Отдельный репозиторий `mityademon-rgb/news`, ветка `boom-kadr-deploy`, содержит действующие GitHub Actions для безопасной доставки на VPS. Это **канал выкладки**, а не источник кода бота.

## 2. Как работает продукт

Один Python-процесс под systemd одновременно обслуживает локальный HTTP, опрашивает Telegram и запускает расписание по Москве. Данные — SQLite. Mini App — статические HTML/CSS/JS, которые отдаёт тот же процесс. Nginx направляет `/tc/` к нему.

Первый `/start` **по обычной ссылке без секретного параметра** знакомит с ботом и предлагает выбрать лабораторию. 25 сентября удалён старый обязательный контроль `JOIN_SECRET`: он мешал детям зайти по опубликованной ссылке `t.me/timemarphino_bot`. Те, кто ранее получил «Доступ по приглашению…», должны нажать «Старт» ещё раз. Повторный `/start` короче. Участники могут не отвечать на переклички; отдельной кнопки разрешения на публикацию нет. Ответы отправляются лично боту. Итоговые выпуски одинаковы для всех подписчиков: **каждому в личный диалог** и **одна копия в подключённый чат взрослых**. Разделения выпусков на Kids и Media нет; детского общего чата в Telegram нет. Взрослый чат видит общие выпуски и фото обеих групп. Личные ответы на вопросы бот в этот чат по отдельности не пересылает.

## 3. Сервер: подтверждённые адреса и пути

| Назначение | Значение |
|---|---|
| SSH-хост, на который успешно подключается GitHub Actions | `root@217.149.24.242` |
| Публичный HTTPS-адрес для `timecode-lab.ru` в текущей конфигурации Nginx | `217.149.24.234:443` |
| Домен Mini App | `https://timecode-lab.ru/tc/` |
| Корень установленного клона | `/opt/timecode-bot` |
| Рабочий каталог и код | `/opt/timecode-bot/timecode-bot/` |
| Служба | `timecode-bot.service` |
| Unit-файл | `/etc/systemd/system/timecode-bot.service` |
| Переменные среды с секретами | `/etc/timecode-bot.env` — **не выводить и не коммитить** |
| SQLite | `/var/lib/timecode-bot/timecode.db` (путь задан unit-файлом) |
| Локальный HTTP | `127.0.0.1:8097` |
| Конфигурация Nginx | `/etc/nginx/conf.d/boom-kadr.conf` |

25 сентября пользователь показал фактический фрагмент Nginx: `location = /tc { return 301 /tc/; }` и `location ^~ /tc/ { proxy_pass http://127.0.0.1:8097/; ... }` в HTTPS-блоке `server_name timecode-lab.ru`. Значит, в тот момент маршрут был **исправен**. Ошибочное первоначальное предположение «Nginx снова слетел» снято. Повторное открытие `/tc/` с параметром версии восстановило отображение у пользователя; точная причина прежнего показа основного сайта не доказана. Не переписывать конфиг из-за одного симптома.

`server.py` читает `PUBLIC_CHAT_ID` из env либо `group_chat` из таблицы `settings`. Администратор может один раз написать `/connect` внутри взрослого чата; бот запоминает ID. Не использовать `/connect kids` как замену: это отдельный маршрут для квестов. Наличие действительного ID взрослого чата после последнего обновления **не проверялось**; личная рассылка работает и без него. Не объявлять, что зеркало чата работает, пока не проверена тестовая публикация именно там.

## 4. Подключение и рабочий способ выкладки

Среда ChatGPT Work, из которой велась работа, **не имеет прямого маршрута TCP/22 к VPS**: `ssh root@217.149.24.234` и `ssh root@72.56.65.161` возвращали `Network is unreachable`. Это ограничение конкретной среды, а не доказательство отсутствия прав. В соседней старой рабочей папке находился ключ для другого сценария; не полагаться на временную папку как на постоянный источник доступа.

**Подтверждённый канал** — GitHub Actions репозитория `mityademon-rgb/news`, ветка `boom-kadr-deploy`. Там уже настроен secret `BOOM_SSH_KEY`; Actions успешно подключился к `root@217.149.24.242` 25 сентября и обновил файлы TIMECODE. Секрет нельзя печатать, копировать в документы или переносить в код. Рабочие одноцелевые workflows:

- [Update TIMECODE arcade](https://github.com/mityademon-rgb/news/actions/workflows/timecode-arcade-update.yml): копирует **только** `arcade.js`, `arcade.css`, адресно обновляет текст/класс в серверном `app.js`, делает резервную копию и проверяет локальный HTTP. Успешная выкладка компактного игрового экрана: [run 36112064749](https://github.com/mityademon-rgb/news/actions/runs/36112064749).
- [Update TIMECODE daily delivery](https://github.com/mityademon-rgb/news/actions/workflows/timecode-delivery-update.yml): копирует `notification_delivery.py`, добавляет вызов `notification_delivery.install(globals())` в серверный `server.py` перед `if __name__=='__main__':`, компилирует, перезапускает службу и проверяет `/health`. Успешная выкладка: [run 36116604043](https://github.com/mityademon-rgb/news/actions/runs/36116604043).
- [Fix TIMECODE direct start](https://github.com/mityademon-rgb/news/actions/workflows/timecode-direct-start.yml): адресно удаляет старый блок проверки секретного параметра у нового пользователя, сохраняет `server.py`, перезапускает службу и проверяет `/health`. [Успешный run 36118123696](https://github.com/mityademon-rgb/news/actions/runs/36118123696).
- [Read TIMECODE bot username](https://github.com/mityademon-rgb/news/actions/workflows/timecode-bot-name.yml): одноразовая проверка публичного username; результат — `timemarphino_bot`. Не нужно повторять при обычных правках.

При изменениях сначала обновлять ветку `feature/timecode-media-bot`, затем запускать **узко ограниченный workflow** с резервной копией и проверками; для новых файлов адаптировать workflow адресно. Проверять `jobs[].conclusion` и журналы шага; зелёный коммит в исходной ветке сам по себе **не означает**, что сервер обновился. После статических правок проверить ответ `http://127.0.0.1:8097/<файл>`, после Python — `python3 -m py_compile`, `systemctl is-active timecode-bot.service`, `curl -fsS http://127.0.0.1:8097/health`. Для визуальных ошибок проверять реальный экран Telegram Mini App на телефоне: синтаксис CSS не доказывает, что стрелки доступны пальцем.

Если у следующего исполнителя есть отдельный разрешённый SSH-канал, сначала выполнить **только чтение**: `hostname`, `systemctl is-active timecode-bot.service`, `git -C /opt/timecode-bot status --short`, `nginx -T` с фильтром маршрута, локальный `/health`. Не выводить `/etc/timecode-bot.env` и токены. До записи сравнить серверные файлы с веткой и сделать копии.

## 5. Самая важная ловушка: сервер ≠ чистый Git

Первый workflow 25 сентября попытался `git -C /opt/timecode-bot pull --ff-only origin feature/timecode-media-bot` и **остановился без изменений**, потому что на сервере есть локальные изменения `server.py`, `app.js`, `index.html`, `style.css` и непроиндексированные файлы игр, квестов, словаря. Это было зафиксировано в [неудачном run 36110619708](https://github.com/mityademon-rgb/news/actions/runs/36110619708). **Не применять `git reset --hard`, `git clean -fd`, автоматический `git pull` или массовый rsync `--delete`: они уничтожат работающие серверные изменения.** Сначала инвентаризировать и сверить изменения; затем перенести нужные части в ветку и выкладывать адресно.

Успешные workflows создали резервные копии:

- каталог последней копии аркады указан в `/opt/timecode-bot/arcade-latest-backup-path` (в нём `app.js`, `arcade.js`, `arcade.css`, если файл существовал);
- каталог последней копии рассылки указан в `/opt/timecode-bot/delivery-latest-backup-path` (`server.py`, прежний `notification_delivery.py`, если он существовал).

При ошибке рассылки workflow автоматически возвращает `server.py`/модуль и перезапускает службу. При ручном откате сначала прочитать путь последней копии, убедиться, что там ожидаемые файлы, и лишь затем восстанавливать. Базу SQLite эти workflows **не меняют и не откатывают**.

У пользователя приложение заработало после повторного открытия ссылки с параметром версии. Причина не подтверждена. Не утверждать, что конфиг исправляли в эту смену.

Исправлено компактным заголовком, высотой поля от `100dvh` и обычным блоком стрелок под полем; workflow завершился успешно. Реальное управление на конкретном телефоне после этой правки пользователь ещё не подтвердил.
3. «Морской бой» заменён поиском двух предметов: камера в верхней правой четверти поля 4×4, микрофон — в нижней левой; четыре открытия клеток на партию. Подсказки показаны перед ходом.
4. С 12:03–12:04 пользователь уточнил модель сообщений: всем одинаковые выпуски в личном боте; взрослому чату — копия общего потока. `notification_delivery.py` подключён поверх старых функций через `install(globals())`, поскольку на сервере есть важные локальные правки `server.py`. **Старые функции в файле остаются, но для перечисленных ежедневных задач во время запуска используются замены из модуля.** При расследовании поведения смотреть оба файла и подтверждать, что импорт/вызов действительно выполнен.
5. Пока не подтверждён живой выпуск после перестройки рассылки. Проверить на следующем событии: один и тот же выпуск виден подписчику Kids, подписчику Media и в чате взрослых; детского отдельного чата нет; нет трёх разных текстов; служба не дублирует Telegram polling. Проверить особенно публикацию фото и доступность `/health`.
6. README в исходной ветке содержит устаревшее описание общих сводок с отдельными блоками Kids/Media и публикации только в чат. **Этот паспорт и текущий модуль рассылки новее README**. При следующих изменениях привести README к фактическому поведению.
7. После приглашения по обычной ссылке несколько детей увидели сообщение «Доступ по приглашению медиацентра…». Причина — проверка `JOIN_SECRET` при первом `/start`. Блок снят на сервере, подтверждены компиляция и запуск службы; живое повторное нажатие «Старт» конкретным учеником ещё не проверено. Теперь по публичной ссылке может зарегистрироваться любой пользователь Telegram, который её получил или нашёл. Не распространять ссылку вне участников; прежде чем публиковать детские фото, учитывать это ограничение доступа.
8. Тесты `timecode-bot/tests/test_server.py` не полностью соответствуют последней логике. В локальном прогоне 25 сентября один тест старой схемы сводок и один тест внешнего поиска падали. Тест первого входа обновлён локально под вход по обычной ссылке; полная регрессия после этой правки не запускалась. Не выдавать это за доказательство сбоя продакшена; добавить тесты на текущую доставку, если меняется маршрутизация. Отдельно проверена функция `tip`: два личных адресата и один групповой в заглушке, без дублей.

## 7. Контрольные точки для следующего исполнителя

- При любом изменении сначала выяснить, **что именно сейчас на сервере**, что в ветке и что видит пользователь; временная рабочая папка не является источником истины для продакшена.
- Не просить Митю многократно копировать диагностические команды. Проверять самостоятельно через уже рабочий GitHub Actions-канал. Если доступ через Actions сломается, объяснить конкретный неудачный шаг и лишь затем просить ровно один необходимый вывод.
- Для вопросов «что реально работает» опираться на фактический запуск, состояние службы и результат конкретного выпуска, а не только на удачную компиляцию или зелёный commit.
- Не публиковать личные ключи, токены, env-файл, идентификаторы чатов и сырой журнал с конфиденциальными данными. Публичные ссылки на репозитории и Actions выше служат ориентиром, но не заменяют проверку доступа.
