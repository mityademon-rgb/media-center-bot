Общий чат Telegram для работы приложения **не требуется**. Бот ориентирован на одну группу; разграничения нескольких групп нет.

## 2. Как входят студенты и староста

**Студент:** получает от старосты персональную пригласительную ссылку вида `https://t.me/kt16info_bot?start=<JOIN_CODE>`, открывает её, нажимает «Старт», затем «Открыть приложение» в сообщении или «Открыть группу» в меню бота. Секретный параметр нельзя публиковать в этом паспорте. Простая ссылка на username **не подходит для первого входа**, если `JOIN_CODE` настроен: бот попросит приглашение. Это намеренное отличие от TIMECODE, где 25 сентября барьер приглашения сняли.

**Староста/резервный администратор:** Telegram ID должен быть в `ADMIN_IDS` на сервере. В личном диалоге с ботом команда `/invite` показывает действующую ссылку для студентов; `/login` выдаёт одноразовый шестизначный код для входа в браузере (5 минут). Встроенное приложение Telegram принимает подписанные `initData` и само авторизует пользователя. Авторизованная браузерная сессия хранится в `sessions` до 30 дней. Не пересылать одноразовый код и пригласительный параметр посторонним.

Команды старосты: `/send Текст` — объявление всем подписанным студентам; документ с подписью `/send Текст` — объявление с файлом; `/invite` — ссылка; `/login` — код. Для любого участника `/mute` выключает личные уведомления, `/start` снова включает. Роль `admin` проверяется по `ADMIN_IDS` и серверной записи; одного знания пригласительной ссылки для доступа к управлению недостаточно.

## 3. Возможности и фактическая механика

- Вкладки Mini App: «Главная», «Расписание», «Лента», «Люди», «Полезное», «Профиль»; у администратора дополнительно «Управление».
- В расписании: пары по дням недели, время начала и конца, предмет, преподаватель, аудитория, подгруппа. В изменениях: дата, привязка к паре, новая информация, пояснение, отмена. Отображение замены поверх пары зависит от `lesson_id`.
- В ленте: объявления, дедлайны, изменения, закреплённые записи, срок действия, документы. Создание поста в панели **не обязательно запускает рассылку**: нужен выбранный `broadcast`; `/send` запускает её напрямую.
- Администратор может добавлять и удалять пары, изменения, преподавателей, ссылки и посты. Загрузка вложения до 20 МБ; файлы хранятся на диске сервера и выдаются через авторизованный `/api/file/<id>`.
- Список участников доступен после авторизации. Номер телефона показывается другим лишь если сам владелец включил `show_phone` в профиле.
- `notify(post_id)` отправляет объявление каждому `users.subscribed=1` лично и фиксирует `sent`/`failed` в `deliveries`. Telegram-пользователь должен предварительно запустить бота, иначе бот не сможет написать ему первым. Запись расписания сама по себе не равна Telegram-рассылке.
- Сервер использует стандартную библиотеку Python, SQLite, long polling Telegram и один HTTP-процесс. Новых npm/Python-пакетов для текущего бота не требуется. Время для клиентского календаря вычисляет браузер; серверные SQL-фильтры используют `date('now')` SQLite. На границе суток по часовым поясам проверить даты отдельно.

## 5. Как подключиться и обновить без риска

В рабочей среде ChatGPT прямой SSH к VPS был недоступен (`Network is unreachable`), но **подтверждён рабочий канал GitHub Actions** репозитория `mityademon-rgb/news`: секрет `BOOM_SSH_KEY` позволяет workflow подключаться к `root@217.149.24.242`. Секрет не должен попадать в код, документы или журналы. Если есть отдельный разрешённый терминал с настроенным ключом, адрес тот же; перед записью сверить `hostname`, `systemctl is-active kino-group.service`, `git -C /opt/kino-group status --short`, локальный `/health`.

Порядок для изменения кода:

1. Обновить ветку `feature/kino-group-miniapp` в `mityademon-rgb/media-center-bot`, проверить Python и JS локально. Не изменять одновременно TIMECODE и основной сайт.
2. Проверить, что серверный клон остаётся на этой ветке и чист: это предусловие `git pull --ff-only`.
3. Использовать [workflow Update kino group bot safely](https://github.com/mityademon-rgb/news/actions/workflows/kino-update.yml) или узкий новый workflow на том же SSH-канале. Он делает `git pull --ff-only`, компиляцию `server.py`, перезапуск `kino-group.service`, проверку локального и публичного `/health` и соседних сайтов. Пример [успешного run 35919725772](https://github.com/mityademon-rgb/news/actions/runs/35919725772).
4. Проверить в Actions результат **конкретного запуска и каждого шага**, затем реальный экран Mini App и Telegram-сценарий, затронутый правкой. Зелёный commit исходников сам по себе не означает выкладку.

[Первоначальный workflow развёртывания](https://github.com/mityademon-rgb/news/actions/workflows/kino-deploy.yml) и установщики `deploy/install.sh`, `deploy/resume-nip.sh` — для **первой установки/незавершённого развёртывания**. Их не повторять на действующей службе: они проверяют отсутствие существующих конфигов и могут прерваться или конфликтовать. Плановый домен `group.timecode-lab.ru` не считать запущенным без отдельной проверки DNS, сертификата и Nginx. Не менять DNS как часть правки кода.

## 6. Данные, резервирование и откат

Сохранять вместе `data/group.db` **и** `uploads/`: база содержит сведения о файлах, а байты лежат на диске. Для согласованной копии SQLite использовать SQLite backup API или остановить службу и скопировать базу вместе с возможными файлами WAL/SHM. Не ограничиваться копией одного `group.db` при работающей службе. Резервная копия должна храниться вне каталога, который перезаписывает кодовая выкладка.

Перед рискованным релизом: записать текущий commit, убедиться, что `git status --short` пуст, сделать резервную копию базы и вложений, затем выкладывать. Если ошиблась только новая версия кода, вернуть предыдущее проверенное состояние Git и перезапустить `kino-group.service`, проверив локальный и публичный `/health`. Если мигрировала база, восстановление кода без согласованной базы может не сработать — подготовить отдельный план отката данных. Не удалять `data/` и `uploads/` командами очистки репозитория.

Ключевые таблицы SQLite: `users`, `sessions`, `codes`, `posts`, `files`, `lessons`, `changes`, `teachers`, `resources`, `deliveries`. У `users` есть роли `pending`, `student`, `admin` и `subscribed`; у ожидающего приглашения `pending` вход в приложение запрещён. Максимальный файл 20 МБ. HTTP-ответы API с авторизацией защищены Bearer-сессией; Telegram WebApp `initData` сверяется через HMAC и время.
